# 技术分工

入墨使用 Kotlin 和原生 Android View。`CaptureService` 作为前台服务管理悬浮入口与编辑窗口，FloatingX 负责系统窗口承载、拖动、吸附和位置保存。

`LocalStore` 保存本地草稿与设置，API 地址单独使用 Keystore 密钥进行 AES-GCM 加密。`SendManager` 在后台发送草稿快照；成功后仅清除与快照仍相同的草稿，避免覆盖发送期间的新编辑。

`FlomoClient` 经 HTTPS 直连个人 flomo webhook，`NoteProtocol` 处理正文、标签和业务结果。`SettingsContent` 供主界面和悬浮设置共用，`SwipeLayout` 处理收起手势并保留输入框与滑块操作。

`AppUpdates` 读取 HTTPS 版本信息，使用 Android DownloadManager 下载，校验哈希、包名、版本和签名，再交给系统安装器确认。

FloatingX 3.0.0 的 core 与 system 模块放在 vendor，保留上游源码和许可，构建文件按应用简化。自动测试采用 Robolectric，系统服务和厂商后台策略仍需手机验证。

# 可调整窗口布局

`PanelLayout` 保存用户选择的 dp 尺寸和相对安全区域左上角的位置；`LocalStore` 按笔记 / 设置、横屏 / 竖屏分开存储。`PanelGeometry` 将偏好投影到当前屏幕可用范围，旧位置超出新屏幕时夹回可见区域。

`PanelWindowController` 监听布局和 WindowInsets，结合屏幕级窗口指标与可见 display frame 判断普通底部输入法占用。默认窗口放在上方并预留普通底部键盘空间。投影只裁剪真正超出可用区的部分，已经放得下时键盘开合不改变尺寸或位置；自动缩小 / 移动不写入偏好，输入法关闭后重新投影原偏好。仅手动拖动结束时保存，拖动取消恢复。只移动窗口时保留用户原先高度，避免把键盘期间的临时高度持久化。

顶部和右下角的 `PanelHandleView` 独占拖动事件流，`SwipeLayout` 对手柄不识别收起手势。FloatingX 继续处理窗口挂载，上游源码未修改。系统浮动键盘可能不报告遮挡区域，用户可手动调整布局。

`OverlayInputController` 管理展开窗口的输入焦点。被动时使用 `NOT_FOCUSABLE + ALT_FOCUSABLE_IM`，不抢其他 APP 的输入，并位于其键盘下方。显式保留 `NOT_TOUCH_MODAL + WATCH_OUTSIDE_TOUCH`，编辑时窗外触摸仍交给底层 APP。展开笔记后在忙碌状态更新完成时主动聚焦正文并请求键盘；设置页保持被动，触摸指定编辑框后进入编辑。两条路径统一移除前两个标志、立即请求编辑焦点并排队请求键盘；窗外事件或失焦立即恢复被动状态。初始请求与触摸请求使用同一可取消任务，不额外安排重复自动聚焦。所有延迟键盘任务带代次检查且可取消，防止快速切换窗口后抢回焦点。仅在仍持有焦点且主动关闭自身输入时调用隐藏键盘，避免影响外部 APP 的输入法。

## 主题

`AppTheme` 根据本地 `ThemeMode` 和当前上下文的系统夜间配置选择配色，默认跟随系统。`Ui` 使用语义颜色与按视图保存的命名绑定；主题变化遍历现有视图更新背景、文字、控件及绘制颜色，不重建布局或重置输入框。修改状态文字颜色时替换对应绑定，不累积回调。

主界面监听主题偏好并处理 `uiMode` 变化，更新系统栏及现有页面。悬浮服务只在屏幕几何配置发生变化时执行原有重建流程，单独的系统主题变化仅更新颜色；设置页也同步主题选项，保留未保存内容。跟随系统和强制模式均使用同一配色入口，悬浮入口的透明度、位置与可见状态独立保留。
